# note — 관리 도구 (manage)

편집기 옆에 붙는 **도구 칸**의 설계. 지금 `App.jsx` 안에 모드별로 흩어져 있는
`tools = { compile, files, bib }` 를 대체한다.

읽는 순서: 「무엇이 바뀌나」 → 「도구 하나의 형식」 → 「모드별 도구」 →
「제안」. 할 일 목록이 아니라 **설계 노트**다.

## 무엇이 바뀌나

- `preview` 는 모드가 아니라 **도구**가 된다. 모드는 `MD` · `원문` · `LaTeX` 셋.
  (`라이브` → `MD` 로 이름만 바뀐다. 파일은 그대로다.)
- `관리` 버튼은 두 모드 모두에 있고, 누르면 **편집기 오른쪽에 도구 칸이 열린다**.
- 제목 줄의 `정보` 접기는 없어진다. 그 안에 있던 것들은 도구 칸의 **공용 칸**으로
  옮긴다. 제목 줄에는 제목과 북마크 리본만 남는다.

## 도구 칸은 편집 칸의 분할이다

새 탭이 아니라 **열려 있는 편집 탭 안의 둘째 열**이다. 이유는 하나다 — 그러면
"따라다니게" 만들 것이 없다. 탭을 바꾸면 같이 바뀌고, 탭을 닫으면 같이 닫히고,
좌우로 보내도 같이 가고, 전체 너비로 펼치면 같이 넓어진다. 따로 뜨는 탭이었다면
그 넷을 전부 손으로 이어줘야 한다.

```
┌ 편집 탭 ─────────────────────────────┬ 도구 칸 ──────────────┐
│ [🔖] 제목                     [관리] │ 공용 | 미리보기 | 목차 │
│ 1  본문…                             │ ┌───────────────────┐ │
│ 2                                    │ │ 날짜   2026-11-02 │ │
│ 3                                    │ │ 파일   …-설계.md  │ │
└──────────────────────────────────────┴ └───────────────────┘ ┘
                                       ↑ 여기를 끌어 너비 조절
```

- 가로 분할은 racklist의 `usePaneSplit` 를 쓴다 (편집 칸 둘을 나누는 그것).
- 너비는 노트마다 기억한다 (`scrolled.js`, 지금 `${id}:tab` 을 두는 자리).
- 좁은 화면에서는 분할 대신 편집기를 덮는다 — 표가 들어가는 칸이라 좁으면 못 쓴다.
- 그림은 RACK 그대로다. 도구 칸의 속은 activity 편집 탭과 같은 **필드 중심**:
  `RackField` · `RackTextRows` 의 라벨-값 줄, 표는 `RackTable`, 버튼은 `rl-btn`.
  새 색도 새 모양도 만들지 않는다.

## 도구 하나의 형식

도구는 파일 하나다. `src-lilak/tools/<id>.jsx` 에 두고, `tools/index.js` 가 모은다.
**도구를 더하는 일 = 파일 하나 + 목록 한 줄.**

```js
// tools/outline.jsx
export default {
  id: 'outline',
  label: 'nt_tool_outline',      // i18n 키. 사전에 없으면 키가 그대로 보인다
  modes: ['md', 'tex'],          // 어느 모드에서 보이나
  badge: (ctx) => null,          // 'dot' | 숫자 | null — 탭과 관리 버튼에 뜬다
  Body: ({ note, edit, go, files, ask, say }) => <…/>,
}
```

```js
// tools/index.js
export const TOOLS = [common, preview, outline, format, figures,
                      compile, refs, bib, comments]
```

모드는 자기 도구를 **고르지 않는다**. `modes` 를 가진 쪽이 도구다. 모드가 목록을
들고 있으면 도구를 더할 때마다 두 곳을 고쳐야 한다.

### ctx — 도구가 쓰는 전부

도구는 본문을 **직접 건드리지 않는다.** 여기를 통해서만 쓴다. 이게 이 설계의
핵심이다 — bib 를 눌러 `\cite{}` 를 넣는 것도, 굵게 버튼도, 목록 만들기도,
전부 아래 네 줄로 끝난다.

```js
{
  note: { id, title, body, fields, tex, dirty },   // 읽기만
  setNote(patch),                 // 제목·머리말 고치기
  edit: {
    put(text),                    // 커서 자리에 넣기
    wrap(before, after),          // 고른 글을 감싸기 (굵게·수식·\textbf)
    lines((line, n) => next),     // 고른 줄들을 줄 단위로 고치기 (목록·주석)
    at(),                         // 커서가 선 줄 번호
    text(),                       // 본문 (읽기)
  },
  go(line),                       // 그 줄로 미끄러져 간다 (이미 있는 기능)
  files, ask, say,                // 노트 폴더, 서버, 알림
}
```

`edit` 는 CodeMirror view 를 감싼 얇은 껍질이고, 도구는 view 를 모른다. 나중에
편집기를 갈아도 도구는 그대로다.

### 지켜야 할 것 셋

- 도구는 **자기 fetch 를 갖지 않는다.** 노트는 편집기가 들고 있다.
- 도구는 **열려 있을 때만 일한다.** 닫힌 도구가 뒤에서 계산하지 않는다.
  예외는 `badge` 하나, 그것도 이미 가진 것(컴파일 오류 수 등)만 센다.
- 도구가 본문을 고치면 **되돌리기 한 번**으로 돌아와야 한다 (한 트랜잭션).

## 모드별 도구

### 공용 (두 모드)

| 도구 | 하는 일 |
|---|---|
| **공용** | `정보` 접기에 있던 전부 — 날짜, 파일 이름, 머리말의 다른 키들, `#태그` 읽기, 폴더 열기, revert, 낱말 수, 줄 북마크 목록과 모두 지우기 |
| **목차** | `#`·`##` (MD) / `\section` (LaTeX) 을 들여쓴 목록으로. 누르면 그 줄로. 두 모드가 **같은 도구**, 파서만 둘 |
| **그림·파일** | 노트 폴더의 파일 목록 (지금 `files` 탭). 작은 그림 미리보기, 누르면 커서 자리에 넣기 — MD 는 `![[이름]]`, LaTeX 는 `\includegraphics`. 드롭 받기. **없는 파일을 가리키는 링크에 경고 점** |

### MD

| 도구 | 하는 일 |
|---|---|
| **미리보기** | 지금 모드였던 그것. 읽는 모습 · 인쇄 · PDF |
| **서식** | 굵게 · 기울임 · 코드 · 링크 · 인용 · 목록으로 만들기 · 표 만들기. `edit.wrap` 과 `edit.lines` 로 전부 한 줄씩 |

그림 크기·이름 바꾸기는 **그림·파일** 도구 안에서 한다 (`![[이름\|300]]` 의 숫자를
고치는 것, 파일 이름 바꾸고 본문의 링크도 같이 고치는 것).

### LaTeX

| 도구 | 하는 일 |
|---|---|
| **컴파일** | 지금 그것. 오류 줄을 누르면 그 줄로 |
| **참조** | `\label` 과 `\ref` 를 맞춰 보여준다. 가리키는 데 없는 `\ref`, 아무도 안 쓰는 `\label` 에 점. 누르면 그 줄로, 또는 커서 자리에 `\ref{}` |
| **bib** | `.bib` 의 항목들 + **몇 번 인용되었는지**. 누르면 커서 자리에 `\cite{}`. 안 쓰인 항목·없는 키에 점. `새 reference` 는 reference_manager 에 만들고 bib 를 다시 쓴다 (이미 있는 `addReference` · `bibText`) |
| **주석** | `%` 로 시작하는 줄 접기 |
| **가져오기·내보내기** | zip import (이미 있음), PDF·zip 내보내기 |

## 제안

### 합치자고 보는 것

- **그림 목록은 두 모드가 같은 도구다.** 다른 건 넣는 글자뿐이다 (`![[x]]` ↔
  `\includegraphics`). `modes: ['md','tex']` 한 줄로 끝나는 게 이 형식의 값어치다.
- **목차도 그렇다.** `#` 과 `\section` 은 같은 것의 두 철자다.

### 커맨트 — 하지 않기로 (2026-11-02)

검토 결과 **안 만든다.** 적어두는 이유는 다시 꺼내지 않기 위해서다.

`13c` 처럼 **줄 번호에 매단 커맨트는 썩는다.** 위에 세 줄을 넣는 순간 13번은 다른
글이다. 북마크도 같은 성질이지만 북마크는 틀려야 "엉뚱한 데로 간다" 로 끝나고,
커맨트는 **엉뚱한 글에 붙은 말**이 된다. 별도 파일에 `{13: "…"}` 로 두면 더
나쁘다 — 노트를 편집기 밖에서 고치면 조용히 어긋난다.

다시 하게 된다면 줄 번호도 사이드카도 아니라 **파일 안의 주석 줄**이어야 한다
(`%% 이 문단 다시 쓰기`). 글 바로 아래 줄이라 글과 함께 움직이고, 공저자에게
그대로 가고, 우리 파일 형식이 늘지 않는다 — 태그를 본문에 두는 이 앱의 규칙과
같다. `주석` 도구의 접기는 그대로 만든다.

### 빼자고 보는 것

- **굵게·기울임 버튼을 위한 탭은 만들지 말자.** 눌러서 칸을 열어야 쓰는 굵게
  버튼은 ⌘B 보다 느리다. 단축키를 먼저 넣고(지금 없다), 버튼은 **서식** 도구
  안에 "이런 게 있다" 는 안내로 두자.
- **표 편집기는 지금 만들지 말자.** `||` + 띄어쓰기로 틀이 나오고 Tab 으로 칸을
  옮기는 게 이미 있다. 칸을 더하고 빼는 버튼 정도가 모자란데, 그건 **서식**
  도구의 줄 두 개다. 제대로 된 표 편집기는 그 두 줄을 써보고 모자랄 때 짓자.

### 더하자고 보는 것

- **깨진 링크 점.** `![[x.png]]` 과 `\includegraphics{x}` 가 가리키는 파일이
  실제로 있는지. 목록을 이미 받아오니 공짜고, 컴파일 실패의 절반이 이것이다.
- **분량.** LaTeX 은 본문만 센 낱말 수 (`%` 줄과 수식 빼고). 투고 규정이 낱말 수로
  오니까. 공용 칸의 한 줄이다.
- **관리 버튼의 점은 모아서 센다.** 각 도구의 `badge` 를 모아 버튼에 하나로.
  지금 컴파일 오류·없는 bib 키에 대해 하는 일을 형식으로 올리는 것뿐이다.

### 따로 적어둘 것

코드블록 안의 `- [ ] 할 일` 이 아직 todos 목록에 뜬다 (태그는 고쳤다). 도구와는
무관하지만 같은 종류의 버그다.

## 순서

**하나.** 도구 칸(분할 + 탭 줄) + `공용` 도구. 여기서 `정보` 접기가 없어지고
지금의 `compile`·`files`·`bib` 가 새 형식으로 옮겨 온다. 보이는 것은 거의 안
바뀌지만 이 뒤의 모든 도구가 한 파일씩이 된다.

**둘.** `목차` 와 `그림·파일` — 두 모드가 도구 하나를 나눠 쓰는 게 되는지 여기서
드러난다. 형식이 틀렸다면 셋을 짓기 전에 안다.

**셋.** MD 의 `미리보기`·`서식`, LaTeX 의 `참조`·`주석`.
